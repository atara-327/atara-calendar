# 要件ヒアリングシート（atara-calendar）

自分専用カレンダーの要件を固めるためのシートです。
ここに書いてもらった内容をもとに、Claude が正式な要件定義書（`docs/requirements/requirements.md`）にまとめます。

> **状況**: 1次ヒアリング回答済み（2026-10-19）。追加質問は [hearing-sheet-2.md](hearing-sheet-2.md) を参照。

---

## 書き方

### 優先度のつけ方（1文字書き換えるだけ）

各項目の先頭の `[ ]` を書き換えてください。

| 記号 | 意味 |
| --- | --- |
| `[M]` | **必須**（Must）。これが無いなら使わない |
| `[W]` | **あったら嬉しい**（Want）。後回しでもいい |
| `[ ]` | 不要 / よくわからない（そのままでOK） |

**Why 3段階なのか**: 最初のバージョン（MVP）に入れるものと後回しにするものを分けるためです。全部「欲しい」だと作る順番が決められず、完成が遠のきます。

### 回答方法は2通り（好きな方で）

1. **このファイルを直接編集する**（GitHub の Web 画面で鉛筆アイコン → 編集 → コミット）
2. **チャットで項目IDだけ送る**。例:
   ```
   V1 M, V2 W, E3 M
   A1: 今はGoogleカレンダー使ってるけど、タスクと予定がバラバラなのが嫌
   ```
   → Claude がこのファイルに反映します。

**全部埋めなくて大丈夫です。** 「わからない」「Claude に任せる」もちゃんとした回答です。
迷った項目は空欄のままにしておけば、あとで Claude から質問します。

## A. そもそも（いちばん大事）

**Why 聞くか**: 「なぜ作るのか」がわかると、細かい機能の要不要を Claude 側でも判断できるようになります。既製品（Googleカレンダー等）で足りない点こそが、このカレンダーの存在意義です。

- **A1. なぜ自分専用カレンダーを作りたい？**
  - 回答:
    1. 月や年の境目が線だけで、ページで分かれていないカレンダーが欲しい（無限スクロールのようなもの）。
       - Why: 従来のカレンダーは月ごとに分かれているが、現実の毎日は連続していて、月が変わっても大きく変わることはないから。
    2. 「1日の予定」と「時間ごとの予定」を分けたい。
       - Why: 従来のカレンダーは、1日の中の予定を立てにくい。例えば「何時から仕事、何時から勉強、何時から家事」のような予定。
- **A2. 今使っているカレンダー/手帳/ToDoアプリは？ 不満な点は？**
  - 回答: A1 の通り。足りなければ補足する。
- **A3. 逆に、今のツールで気に入っていて残したい点は？**
  - 回答:
    1. ワークスペースを複数に分けられて、同時に表示もできる。
       - Why: 仕事用・趣味用などで分けたいから。
    2. 毎日・毎週・毎月・毎年・第n◯曜日などの繰り返し予定を立てられる。変更・削除は一括でも個別でもできる。
- **A4. これが出来たら「作ってよかった」と思える瞬間は？**（例: 朝スマホを開いて今日やることが一目でわかる）
  - 回答: 予定が何週間後・何日後なのかがパッと見でわかること（月を行ったり来たりして考えなくていい）。

## P. 使う環境

**Why 聞くか**: Webアプリにするかスマホアプリにするかで、技術選定・開発量・費用がまるごと変わるためです。

- [M] **P1.** PC のブラウザで使う
- [M] **P2.** スマホ（iPhone）で使う ※ブラウザで動けばいい
- [M] **P3.** スマホ（Android）で使う ※ブラウザで動けばいい
- [ ] **P4.** スマホのホーム画面にアプリっぽく置きたい（PWA） → 不要
- [M] **P5.** オフライン（電波なし）でも見られる/編集できる → 一瞬オフラインになっても動いてほしい
  - Why: 電車で電波がつながらないことがあるから。
- [M] **P6.** 複数端末でデータを同期したい（PCで入れた予定がスマホにも出る）
- **P7. その他・補足:** ブラウザで動けばいい。スマホとPCの両方に対応する。

## V. 表示（画面）

**Why 聞くか**: 毎日いちばん長く見るのは表示画面なので、使う表示から優先して作り込みます。

- [M] **V1.** 月表示（よくあるカレンダーのマス目） ※A1 の「無限スクロール」で
- [ ] **V2.** 週表示（時間軸つき） → 不要
- [M] **V3.** 日表示（1日のタイムライン）
  - 1日の予定を立てるためのもの。カレンダーとは別の機能と考えてもいい。
  - イメージ: 月表示には「帰省」とだけ書いてあって、日表示には「◯時 飛行機、◯時 電車」のような細かい情報が載っている。
- [ ] **V4.** リスト表示（今後の予定を縦に並べる） → 不要
- [ ] **V5.** 年表示 → 不要
- [M] **V6.** 起動したときに最初に出てほしい画面 → **月表示**
- [ ] **V7.** 週の始まりを月曜にしたい → 不要（日曜始まりと解釈。2次ヒアリングで確認）
- [M] **V8.** 日本の祝日を表示 → 祝日と祭日をそれぞれ（意味は2次ヒアリングで確認）
- [ ] **V9.** 六曜（大安・仏滅など）を表示 → 不要
- **V10. その他・補足:**

## E. 予定（イベント）の機能

**Why 聞くか**: 予定データに持たせる項目（データ構造）を最初に決めておかないと、後から足すときに作り直しが発生しやすいためです。

- [M] **E1.** 予定のタイトル・日時・終日予定
  - 月表示: 従来のカレンダーと同じ感覚で、日ごとに予定を入れる。項目はタイトルと日時。日ごとの予定だけど、時間まで指定できてほしい。
  - 日表示: 予定表の感覚。項目は主にタイトルと日時。
  - 場所や詳細は、月表示の予定にも日表示の予定にもそれぞれあっていい。
- [M] **E2.** 繰り返し予定（毎週○曜、毎月○日、など） ※A3 の通り
- [M] **E3.** 色分け / カテゴリ（仕事・プライベートなど）
- [M] **E4.** メモ欄
- [M] **E5.** 場所（地図リンク）
- [M] **E6.** URL（会議リンクなど）
- [M] **E7.** 複数日にまたがる予定（旅行など）
- [W] **E8.** ドラッグ＆ドロップで日時を移動
- [W] **E9.** 予定の検索
- [ ] **E10.** 予定のテンプレート（よく入れる予定をワンタップで） → 不要
- [W] **E11.** 写真・ファイルの添付
- **E12. その他・補足:**

## T. タスク / ToDo

**Why 聞くか**: 「予定」と「タスク」を一緒に扱うかどうかで、アプリの性格が大きく変わる（カレンダー寄りか、タスク管理寄りか）ためです。

- [ ] **T1.** ToDo（日時のないやること）も管理したい → 不要
- [ ] **T2.** 期限つきタスクをカレンダー上に表示 → 不要
- [ ] **T3.** タスクを予定の時間枠に割り当てる（タイムブロッキング） → 不要
- [ ] **T4.** 習慣トラッカー（毎日やったか記録する） → 不要
- [ ] **T5.** 日記・1日のふりかえりメモ → 不要
- **T6. その他・補足:** T はすべて不要。

## I. 入力方法

**Why 聞くか**: 予定を入れるのが面倒だと結局使わなくなるので、入力の手軽さは継続して使えるかどうかに直結します。

- [M] **I1.** フォームで普通に入力
- [ ] **I2.** 文章で入力（例: 「明日15時 歯医者」→ 自動で予定になる） → 不要
- [W] **I3.** AI（Claude など）に話しかけて予定を入れる・相談する
  - Claude 経由で予定の確認・追加・サマリができたら面白い。MCP 経由を想定。（優先度は2次ヒアリングで確認）
- [ ] **I4.** 音声入力 → 不要
- [ ] **I5.** キーボードショートカット → 不要
- **I6. その他・補足:**

## X. 外部連携

**Why 聞くか**: 他サービスとの同期は実装コストが大きく、片方向（読むだけ）か双方向かでも難易度が数倍違うためです。

- [ ] **X1.** Googleカレンダーの予定を**表示**する（読むだけ） → 不要
- [ ] **X2.** Googleカレンダーと**双方向**同期（どちらで編集しても反映） → 不要
- [ ] **X3.** iCloud / Outlook カレンダーと連携 → 不要
- [ ] **X4.** iCal（.ics）の読み込み・書き出し → 不要
- [ ] **X5.** Notion と連携 → 不要
- [ ] **X6.** 他人と予定を共有する → 不要
- **X7. その他・補足:** 外部連携はすべて不要（Claude の MCP 連携は I3 で扱う）。

## D. データ・セキュリティ

**Why 聞くか**: 予定は個人情報のかたまりなので、どこに保存して誰がアクセスできるかを最初に決めておく必要があるためです。

- [M] **D1.** ログイン（自分以外が見られないようにする）
  - いちばん簡単なのは Cloudflare Zero Trust かな。（方式は2次ヒアリングで確認）
- [ ] **D2.** データは自分の端末だけに保存でいい（クラウドに置かない） → 不要
- [M] **D3.** クラウドに保存して、どの端末からでも見たい
- [W] **D4.** 自動バックアップ
- [W] **D5.** データを丸ごとエクスポートできる（乗り換え・保管用）
- **D6. その他・補足:**

## U. 見た目・使い心地

**Why 聞くか**: 自分専用なので「自分が気持ちよく使えるか」が最優先。好みを先に知っておくとデザインの手戻りが減ります。

- [M] **U1.** ダークモード
- [ ] **U2.** 好きな色・テーマを選べる → 不要
- [ ] **U3.** 片手操作しやすいスマホUI → 不要
- **U4. 好きなデザインのアプリ・サイト（参考にしたいもの）:** Googleカレンダー
- **U5. 嫌いなデザイン・やめてほしいこと:** AIっぽいデザイン
  - どんなデザインがAIっぽいのかはリサーチして避けてほしい（グラデーションを多用する、など）。
  - → デザイン工程の最初に Claude がリサーチして、結果を docs にまとめてから進める。
